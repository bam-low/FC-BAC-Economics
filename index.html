Расчёт экономики роботизации: рабочий бриф команды

Собранный план, формулы и открытые вопросы для старта работы. Один документ вместо переписки.

Контекст в двух словах

Что мы вообще делаем и зачем этот документ.

ЗАДАЧА
Платформа сравнивает базовый сценарий (живой труд) с 2+ сценариями роботизации — покупка и услуга (RaaS) — по CAPEX, OPEX, эффекту, окупаемости, ROI, TCO.
МОЯ РОЛЬ
Экономическая модель: формулы, допущения, финансовая логика. Не парсинг каталога, не фронтенд — но контракт данных и проверка расчёта — да.
ЧТО УЖЕ ЕСТЬ
Готовые нормализованные датасеты по складу, аэропорту и медучреждению (Excel, с базовыми значениями и диапазонами).
ЧЕГО ЕЩЁ НЕТ
Каталог роботов с ценами — сырой, придёт отдельно. Финансовые допущения (амортизация, заём, RaaS) — не зафиксированы, это на нас.

Хронология работы

Порядок шагов от старта до готового расчётного модуля. Метки показывают, что можно делать сразу, что требует решения и что — совместно с разработкой.

Изучить датасеты объекта

Выбрать из готового Excel только те параметры, которые реально нужны формулам (не все ~50 полей пойдут в расчёт).

МОЖНО СЕЙЧАС
Зафиксировать финансовые допущения

Финансирование (свои средства / кредит / лизинг), метод и срок амортизации CAPEX, точный состав статей CAPEX/OPEX, логика платежей для RaaS.

ТРЕБУЕТ РЕШЕНИЯ
Определить контракт полей каталога роботов

Список характеристик робота (цена, производительность, грузоподъёмность, срок службы, стоимость обслуживания) и единиц измерения — передать тому, кто готовит каталог.

ТРЕБУЕТ РЕШЕНИЯ
Построить формулы

Полная цепочка: количество роботов → CAPEX → OPEX → годовой эффект → срок окупаемости → ROI → TCO. Отдельно для покупки, отдельно для RaaS.

МОЖНО СЕЙЧАС
Проверить модель вручную на демо-данных

Прогнать формулы в Excel на базовых значениях склада для 2–3 условных роботов — получить эталон для сверки после программирования.

МОЖНО СЕЙЧАС
Реализовать движок расчёта в коде

Перенос формул и допущений в код, который принимает параметры объекта и робота и отдаёт все метрики.

СОВМЕСТНО С РАЗРАБОТКОЙ
What-if пересчёт и экспорт отчёта

Пересчёт при изменении ключевых параметров (мин. 3 — труд, объём операций, оборудование) + выгрузка отчёта в PDF/Excel с пометкой «предварительная оценка».

СОВМЕСТНО С РАЗРАБОТКОЙ

Ключевые формулы

Базовая логика расчёта (по ТЗ, п. 3.5.2) — отправная точка, детали статей уточняются в допущениях ниже.

ПоказательФормулаКомментарий
Кол-во роботов пик. потребность / (произв. робота × загрузка) с учётом резерва и доступности оборудования
CAPEX оборуд. + инфра + ПО + интеграция + пусконаладка + обучение + резерв резерв обычно ~10%
OPEX сервис + лицензии + энергия + связь + расходники + ремонт + персонал для RaaS часть статей уходит в арендный платёж
Годовой эффект экономия затрат + доп. доход − доп. OPEX включает экономию ФОТ (коэфф. начислений 1.302)
Срок окупаемости CAPEX / годовой эффект простой, при положительном эффекте
ROI накопленный эффект / CAPEX × 100% горизонт задаётся пользователем
TCO CAPEX + Σ OPEX за 5+ лет с учётом замены компонентов (напр. АКБ раз в 3–5 лет)

Допущения, которые нужно решить до кода

Организаторы прямо оставили это на усмотрение команды — без явного решения формулы будут неоднозначными.

  • Финансирование Базово — собственные средства. Решить: добавляем ли вариант с кредитом/лизингом (ставка, график платежей)?
  • Амортизация CAPEX Выбрать метод (обычно линейный) и срок службы оборудования.
  • Состав статей CAPEX и OPEX Что именно входит в каждую статью — для сценариев покупки и услуги отдельно, согласовать с демо-данными.
  • Логика RaaS (аренда) Структура платежей (фикс / за использование / смешанная), срок контракта, условия выкупа, распределение между CAPEX и OPEX.
  • Правила исключения решений По каким техническим ограничениям робот не подходит объекту (габариты, масса, точность позиционирования, безопасность).
